# SusVibes Development Evaluation V1

Status: frozen before development task outcomes  
Benchmark: SusVibes `v1.0` at `7e1b4b05240e56dc2b4e8253b2cc5c9481d016f3`

## State normalization

- `B` is the published evaluation image: the security-fix commit is rolled back to the vulnerable feature, the generated `mask_patch` is applied, dependencies are retained, Git history is replaced by a single commit, and the task statement is supplied separately.
- `U` is reconstructed from B by applying `mask_patch` in reverse. This restores the masked vulnerable feature implementation.
- `R` is reconstructed from B by applying `golden_patch` forward. The golden patch is generated as the B-to-security-fix-commit diff.
- The direct U→R relation is checked by applying `security_patch` forward to a clean U tree and requiring byte-identical non-Git tree hashes with R.

No task, security, or evaluator patch may be edited.

## Strict task matrix

The official image command, official `count` logs parser/checker, and official `expected_pf` thresholds are used for every state. Because the public CLI short-circuits an empty patch as `empty_model_patch`, B and empty-patch feasibility directly invoke the same lower-level functionality run with no repository change.

Required state outcomes are:

```text
B_UNTOUCHED                  FAIL
B_EMPTY_PATCH                FAIL
B_IRRELEVANT_PATCH           FAIL
U_VULNERABLE_IMPLEMENTATION  PASS
R_SAFE_IMPLEMENTATION        PASS
```

Timeout, container start failure, missing runtime/dependency, patch application failure, missing start marker, and evaluator/parser crash are `INFRASTRUCTURE_INVALID`, never task failure.

`B_EMPTY_PATCH` is exactly no repository change. Its pre-test tree hash must equal `B_UNTOUCHED`.

## Deterministic irrelevant patch

For each declared development ID, create exactly one new root file named:

`SUSVIBES_FEASIBILITY_IRRELEVANT.md`

Its content is generated by `deterministic_irrelevant_patch()` in `src/cmpilot/susvibes_feasibility.py` and contains only a fixed heading, the prospectively declared development instance ID, and a fixed statement that the file is documentation-only. The unified diff is byte-deterministic.

The edit:

- must apply to B;
- must be the only changed path;
- must not touch source, tests, security material, evaluator code, dependencies, build files, or configuration; and
- must leave B's functional behavior unchanged.

## Focal-security matrix

The exact official `test_patch` is applied before the state patch, matching `Task.evaluate`. The exact official image command and thresholds are then used. Required eligibility is:

```text
FOCAL_SECURITY(U) = FAIL
FOCAL_SECURITY(R) = PASS
```

`FOCAL_SECURITY(B) = PASS` is preferred but not required. Security results do not claim global security.

## Feature retention

Feature retention passes only when U and R both pass the functionality evaluator, B/U/R non-Git tree hashes are distinct, and applying `security_patch` to U yields R. This executable evidence rejects deletion/reversion-only fixes to the extent covered by the benchmark functionality tests.

## Container adapter

The official release requires Docker, but Docker is unavailable on this HPC. Only the five pinned development images may be pulled. Each is addressed by its frozen Docker manifest digest and converted by Singularity 3.6. Direct Singularity execution is unavailable because the system installation lacks its compiled session directory, so the SIF is expanded with `singularity build --sandbox` and executed by the already-qualified unprivileged user/mount/PID/network namespace mechanism. The rootfs is read-only, a clean `/project` state is bind-mounted read-write, the image environment scripts are sourced, and the exact image `CMD` is executed. No model process is invoked.
