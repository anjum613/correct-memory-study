\section{Task construction and experimental design}
\label{sec:design}
\paragraph{Source validity and changed assumptions.}
Each family pairs a source setting in which a procedure is valid with a target feature request that changes a relevant assumption. The final suite contains six F-series and seven X-series synthetic families. A source-valid procedure is neither an adversarial instruction nor a guarantee of target correctness. Existing baseline code is visible in every condition: no memory removes the supplied memory, not the task's existing implementation. Appendix~\ref{app:families} lists the family definitions and bounded witness scopes.


\paragraph{Reference controls.}
Before target-agent execution, the saved preflight checks three target states for every family: the incomplete baseline must fail functionality while passing the focal witness; an unadapted functional reference must pass functionality and fail the witness; and a repaired reference must pass both. These roles establish that avoiding the requested feature is not sufficient for success. The admitted synthetic artifacts and source procedures are fixed by the final cohort manifest. Constructors and evaluated agents are distinct roles; the former do not receive the sealed witness or evaluated-agent outcomes.

\paragraph{Configurations and execution.}
The final dataset contains \RecordedRuns{} recorded runs, \ValidRuns{} technically valid and \InvalidRuns{} invalid. Each of the six configurations completes its 104-run schedule. Codex and MiniSWE use different native execution interfaces and instruction envelopes. Model aliases are reported exactly as requested; revisions are given where recorded and are not inferred where unavailable. Run order is saved in the executed manifests. The prescribed comparisons use the final configurations, not earlier development runs. Appendix~\ref{app:corrections} records the excluded unfinished configuration and scoring history.

\paragraph{Memory conditions.}
The conditions are no memory (N), source-correct memory (C), matched irrelevant memory (I), and source-correct memory with a generic applicability boundary (B). The C, I, and B envelopes contain 4,096 bytes including neutral padding; N has no envelope. This equalizes bytes among the memory conditions, not token counts. The B reminder asks the agent to check whether the source assumption still holds and supplies no family-specific target repair. C$-$N is the frozen primary contrast; I$-$N and B$-$C are secondary.

\paragraph{Outcomes.}
For a technically valid run, $F$ denotes functionality pass and $S$ denotes focal-security-witness pass. The primary endpoint is
\begin{equation}
 U = F\land\neg S.
\end{equation}
We report all four joint outcomes. In particular, $\neg F\land S$ is an incomplete implementation that passes the focal witness; it is not successful security adaptation. $F\land S$ is described as \emph{functionality and focal-witness pass}, without implying full-contract or general security. Technical invalids retain missing F/S/U values for analysis, including cases with intermediate raw flags. Termination labels do not replace evaluated outcomes.

\paragraph{Scoring version.}
The analysis uses the versioned contract-validity correction, which changes four false security passes in Devstral and no functionality scores. The X05 and X28 corrections observe the returned behavior required by the original contracts, rather than relying solely on optional bookkeeping. Original scores remain preserved, and Appendix~\ref{app:corrections} reports both versions. X06 retains its original confidentiality witness: rejection before output can pass that test without demonstrating selective redaction or complete retention of public diagnostics.

\paragraph{Analysis unit and eligibility.}
For each configuration and contrast, both repetitions must be valid and have observed F and S in each compared condition. We first average repetitions within family and condition, then average paired differences equally over eligible families. Each table reports its eligible family count. Repetitions are repeated executions, not independent task families. Comparisons within configuration are primary; model identity, harness, tools, and budgets change together across configurations and therefore do not support an intrinsic model-security ranking.

\paragraph{Uncertainty and behavioral evidence.}
We recompute all estimates from the corrected row table. Exploratory percentile bootstrap intervals resample paired families, preserving their repetitions; exact sign-flip and leave-one-family-out diagnostics are reported separately. These quantify variation within a small selected task set, not representative population uncertainty. Behavioral examples link visible transcripts, saved patches, and evaluator outcomes. The original outcome hypothesis is retained; mechanisms identified through subsequent case selection are exploratory.
