             Procedural Memory Across Trust Boundaries:
             A Controlled Study of Coding-Agent Behavior

                                                         Abstract
 1             A procedure can be correct in the setting where it was learned and inappropriate
 2             in the setting where it is reused. We study this distinction in coding agents by
 3             supplying source-valid procedural memory while changing a security-relevant
 4             assumption in the target task. Thirteen synthetic task families cross four memory
 5             conditions with two repetitions in each of six model–agent configurations, yielding
 6             624 recorded runs and 595 technically valid outcomes. The primary endpoint is
 7             functional completion that fails a bounded security witness. Within-configuration
 8             comparisons do not establish a uniform harmful-memory effect. Correct-memory
 9             contrasts vary in direction; lower failure rates can accompany reduced functionality.
10             A generic applicability reminder reduces the endpoint descriptively in the three
11             Codex configurations but has no consistent benefit in MiniSWE. Selected transcript–
12             implementation–outcome comparisons show both procedure-consistent failures
13             and successful adaptation, including cases where correct memory itself makes a
14             changed assumption salient. These findings concern supplied memory in shifted
15             synthetic contexts, not an end-to-end retrieval system. They show why memory
16             transfer must be assessed jointly with functionality, witness scope, and the agent’s
17             execution interface.


18   1    Introduction
19   Procedural memory gives an agent a way to reuse a successful method without deriving it again.
20   Yet success is conditional. A length-delimited record may have been complete before it reached
21   a parser; a cache may have belonged to one request; a diagnostic object may have contained only
22   public fields. When the target changes these assumptions, the remembered procedure can remain an
23   accurate account of the source task while becoming an incomplete guide to the new one.
24   We ask: when a coding agent receives a source-valid procedure in a target context where its
25   assumptions no longer hold, how does that memory change functional completion and focal security
26   failures? A second question asks whether a generic reminder to check applicability changes that
27   behavior. The intervention is deliberately small: supply a frozen procedural memory, supply a
28   matched irrelevant memory, append an applicability reminder, or supply no memory. The target task
29   and its changed assumption are held fixed across these conditions.
30   Our original hypothesis was that source-correct memory would increase functional completions that
31   violate the target’s focal security property. The completed experiment does not support this as a
32   general effect. Across six configurations, the corrected primary contrast has both positive and negative
33   point estimates, with substantial uncertainty. This result does not make the intervention behaviorally
34   inert. Matched cases reveal unchecked reuse in some runs, recognition of source limitations in others,
35   and failures to complete the task that would be mistaken for security improvements if functionality
36   were omitted.

37   The study makes three contributions. First, it operationalizes source-valid but target-inapplicable
38   procedural memory in thirteen controlled synthetic families with separate functionality and security
39   witnesses. Second, it reports corrected, within-configuration treatment comparisons and the full joint
40   outcome distribution, preserving technical invalidity as missing measurement. Third, it connects
41   selected visible transcripts to saved implementation changes and evaluated outcomes, showing why
42   neither a witness failure nor silence about memory establishes how a procedure was used. These are
43   behavioral case studies selected after outcome inspection, not estimates of behavioral prevalence.
44   The scope is intentionally specific. All experimental targets already contain a context shift; there is
45   no randomized unshifted target arm. The design estimates the effect of supplying memory under
46   those conditions, not the effect of shift itself. Memories are supplied directly, so retrieval quality,
47   memory selection, and online memory formation are outside the intervention. The synthetic setting
48   supports controlled comparisons but does not establish performance in real repositories.

49   2   Related work
50   Memory and applicability. Voyager stores reusable executable skills, while ExpeL extracts natural-
51   language lessons from experience without updating model parameters [Wang et al., 2023, Zhao et al.,
52   2023]. These systems motivate procedural reuse, but successful transfer is conditional on what
53   the memory preserves. Kim et al. [2026] study four memory representations across six coding
54   benchmarks and find that abstract insights transfer more reliably than concrete traces. Our experiment
55   fixes a source-valid procedure and changes its relevance to a target security contract; the endpoint
56   distinguishes task non-completion from a functional security violation.
57   Boundary-Aware Skill Memory (BASM) is the closest applicability-aware method [Lin et al., 2026].
58   It augments skills with applicability conditions, risk cues, avoidance rules, and recovery notes, and
59   combines retrieval, boundary-conditioned execution, and local repair. It also investigates wrong-
60   tool preference using attention and intervention analyses. Our B arm is a single generic reminder
61   attached to a supplied memory. It neither implements BASM nor tests its structured mechanism. The
62   contribution here is a controlled outcome decomposition for coding under changed trust assumptions,
63   together with visible implementation evidence. We do not claim novelty for the general observation
64   that relevant skills can be inapplicable.

65   Skill-induced regressions. SWE-Skills-Bench measures the marginal utility of supplied skills
66   in repository-based software tasks and reports limited average gains and context-compatibility
67   failures [Han et al., 2026]. Dong et al. [2026] use differential analysis of paired runs to examine
68   functional failures and efficiency regressions induced by loaded skills. Their results make clear that
69   procedural guidance can constrain implementation in unhelpful ways. Our focal distinction is between
70   failing to implement a feature and implementing it while violating a separately evaluated security
71   property. The selected case studies are complementary evidence, not a new validated attribution
72   method.

73   Security and the execution interface. SecureVibeBench reconstructs vulnerability-introducing
74   scenarios in 105 C/C++ tasks from 41 OSS-Fuzz projects and combines functionality and security
75   evaluation [Chen et al., 2026]. We cite its ACL 2026 version, which supersedes the earlier arXiv
76   report. Its repository realism addresses a different objective from our synthetic memory intervention.
77   Experience-driven self-evolution can also trade safety against task utility in web and embodied
78   settings [Zhao et al., 2026]; our measured behavior is the generated implementation rather than
79   refusal of a harmful request. Finally, SWE-agent demonstrates that the agent–computer interface
80   affects software-engineering performance [Yang et al., 2024]. This matters directly here: different
81   tool surfaces and execution budgets are part of each evaluated configuration, and interface-related
82   non-completion changes the meaning of an apparent security pass.

85   is valid with a target feature request that changes a relevant assumption. The final suite contains six
86   F-series and seven X-series synthetic families. A source-valid procedure is neither an adversarial
87   instruction nor a guarantee of target correctness. Existing baseline code is visible in every condition:

90    Reference controls. Before target-agent execution, the saved preflight checks three target states
91    for every family: the incomplete baseline must fail functionality while passing the focal witness;
92    an unadapted functional reference must pass functionality and fail the witness; and a repaired
93    reference must pass both. These roles establish that avoiding the requested feature is not sufficient for

97    Configurations and execution. The final dataset contains 624 recorded runs, 595 technically valid
98    and 29 invalid. Each of the six configurations completes its 104-run schedule. Codex and MiniSWE
99    use different native execution interfaces and instruction envelopes. Model aliases are reported exactly
100   as requested; revisions are given where recorded and are not inferred where unavailable. Run order is
101   saved in the executed manifests. The prescribed comparisons use the final configurations, not earlier
102   development runs. Appendix C records the excluded unfinished configuration and scoring history.

103   Memory conditions. The conditions are no memory (N), source-correct memory (C), matched
104   irrelevant memory (I), and source-correct memory with a generic applicability boundary (B). The C,
105   I, and B envelopes contain 4,096 bytes including neutral padding; N has no envelope. This equalizes
106   bytes among the memory conditions, not token counts. The B reminder asks the agent to check
107   whether the source assumption still holds and supplies no family-specific target repair. C−N is the
108   frozen primary contrast; I−N and B−C are secondary.

109   Outcomes. For a technically valid run, F denotes functionality pass and S denotes focal-security-

134   4   Results

135   The primary hypothesis is not established across configurations. Table 2 reports the corrected
136   within-configuration comparisons. The C−N point estimates for U are +9.1, +13.6, and +4.2
137   percentage points for GPT-5.5, Luna, and Terra respectively, versus 0.0, −11.5, and −4.2 for Qwen-
138   Next, Qwen-30B, and Devstral. The direction therefore depends on the evaluated configuration.
139   These small, selected sets of families do not establish a common harmful-memory effect, and a zero
140   or negative estimate does not establish equivalence or absence of local harm.

141   A reduction in U need not be a security improvement. For Qwen-30B, C−N reduces U by -11.5
142   points while reducing functionality by -15.4 points. Across all thirteen eligible families, functional
143   runs fall from 24 to 20 out of 26, and functionality-and-focal-witness passes fall from 8 to 7. Thus the
144   lower U is not a functionality-preserving improvement. Devstral differs: its corrected C−N estimate
145   is -4.2 points while functionality increases by +4.2 points. The same endpoint direction can arise
146   from different changes in joint outcomes.
147   Figure 1 retains all recorded runs by condition. Qwen-Next has 38 valid ¬F ∧ S outcomes, all with
148   unchanged final implementations in the saved audit. Luna has 18 such outcomes; sixteen have empty
149   patches and visible complaints about unavailable named tools. These are concrete non-completions.
150   They explain why the focal-witness pass rate alone is an inadequate measure of successful coding.

161   The irrelevant control does not behave uniformly. The I−N estimates range from −8.3 to
162   +7.7 points across configurations. Irrelevant memory is consequently not an inert placebo in every
163   observed cell. It controls for supplying a memory envelope and a source-valid procedure from a
164   different mechanism; it does not remove all semantic or sampling differences. The supplementary
165   C−I comparisons use the same eligibility rule and remain exploratory.

185   5   Exploratory behavioral analysis
186   The two audit casebooks were assembled after observing outcomes, using programmatic retrieval
187   and selected close reading. The saved Codex coding fields are pending or unavailable for interrupted
188   runs; no completed independent coding of the experiment’s behavior was found. We therefore use
189   selected cases to compare visible statements, saved edits, and corrected outcomes. We do not estimate
190   uptake prevalence, inter-rater reliability, or mediation. A statement about memory is evidence of an
191   expressed rationale; its causal role in the edit requires more than temporal proximity.

192   A remembered procedure can survive without its precondition. In F01, source completeness
193   permits a length-and-slice procedure. The target must handle a length prefix at a less trusted boundary.
194   The C/r2 statement and saved edit in Table 3 agree on slicing and storage without checking available
195   payload length; functionality passes and the focal witness fails. The other C repetition checks
196   completeness and passes both. N and I each have two functionality-and-focal-witness passes for this
197   configuration. This is a localized memory-associated failure with a same-treatment counterexample.
198   It supports neither deterministic copying nor a claim that every use of C causes harm.

199   Applicability reasoning can change when protection is established. In X11, the C/r1 plan
200   uses the source’s inherited permissions and narrows access later. Its final implementation passes
201   functionality but fails the creation-time confidentiality witness. B/r1 explicitly questions whether
202   default readers are authorized, restricts access at creation, and passes both checks. The distinction is
203   the timing of the protection, not merely whether permissions appear somewhere in the patch. Both C
204   repetitions fail the witness and both B repetitions pass it. This is a matched behavioral illustration of
205   the observed B benefit, not evidence that the reminder always supplies sufficient guidance.

206   Correct memory can itself draw attention to a changed assumption. F08 provides counterevi-
207   dence to a uniformly harmful interpretation. The source memory explains why numeric status values
208   can be interpolated into HTML. The N/r1 implementation extends that interpolation to the supplied
209   label. C/r1 instead states that the value is no longer guaranteed numeric and escapes it as text. Both
210   are functional, but only C passes the focal witness. Both C repetitions and both B repetitions pass
211   both checks, whereas N and I each produce two functional witness failures. No extra boundary
212   sentence was necessary in these C executions.

213   Similar outcomes need not have the same mechanism. All twenty-four Codex F02 runs complete
214   functionally and fail the focal witness, including N and B. The saved audit finds invocation-time
215   reopening or rereading in all final patches, whereas the unadapted reference captures a record and
216   reads it after its lease ends. Both can return a changed value, but they are different implementation
217   mechanisms. A witness failure alone therefore cannot establish copying. The Qwen-Next F02/B/r2
218   counterexample stores a precomputed formatted value and passes both checks. Its visible memory
219   recheck occurs after the edit, so it corroborates verification of the solution rather than establishing
220   what caused the edit.
221   One further case explains why contextualizing a quote matters. In Devstral F20/C/r2, a visible sum-
222   mary describes source-memory steps as being outlined in the task, and the final implementation fails
223   the focal origin witness. This suggests that source guidance was promoted into a target requirement.
224   Yet all MiniSWE F20 conditions produce functional witness failures, so this case cannot establish
225   a marginal memory effect. Failure, expressed uptake, and a treatment contrast answer different
226   questions.


227   6      Discussion and limitations

228   A source-valid memory provides both a procedure and evidence about the circumstances in which it
229   worked. The observed agent behavior is consistent with either component becoming salient. Some
230   implementations preserve the source procedure without the target check; others use the stated source
231   assumption to identify what must change. The successful F08 C runs show why a one-direction


                                                              7
232   account of memory as harmful imitation is incomplete. They also explain why adding a boundary
233   reminder can have little marginal benefit when the source text already supports applicability reasoning.
234   Three evaluation choices are consequential. First, functionality and the focal witness must be reported
235   jointly. A task left at its baseline may avoid the behavior the security test observes, but it has not
236   met the feature request. Second, a witness must observe the contract-relevant return value or effect.
237   Reference controls alone did not prevent the X05/X28 bookkeeping defects exposed by alternative
238   agent implementations. Third, invalidity can depend on the implementation: an agent may recognize
239   the main authority boundary yet fail on its error path. Treating such runs as unrelated outages would
240   misstate what is missing.
241   These implications support better memory evaluation, but the experiment has a narrow reach. Thirteen
242   deliberately constructed families with two repetitions per cell provide limited precision and are not a
243   probability sample of software work. The tested memory is supplied directly and does not evaluate
244   retrieval, online learning, or the causal effect of context shift. Prompt bytes are balanced among
245   memory conditions, but tokens and information content are not identical. Tool instructions, provider
246   prompts, and budgets differ across harnesses, so the observed cross-configuration differences cannot
247   be assigned to model weights alone.
248   The security outcomes are bounded by their executed witnesses. X06 rejection is evidence of
249   confidentiality on one mixed fixture, not full retention or general redaction. The X05 correction
250   observes emitted packets and does not establish arbitrary concurrent allocator behavior. The other
251   families were not exhaustively audited for all possible contract violations. Finally, the behavioral
252   analysis is selected and outcome-aware: visible statements can corroborate implementation changes,
253   but they do not reveal all internal computation or establish causal mediation. The study supplies
254   evidence for conditional transfer and for measurement distinctions that future, larger evaluations
255   should preserve.

256   7   Conclusion
257   Supplying correct procedural memory under changed trust assumptions produced heterogeneous out-
258   comes in this controlled coding study. The original harmful-memory hypothesis was not established
259   as a general effect. Local harmful transfer, successful adaptation, and non-completion all occurred,
260   and a generic applicability reminder helped descriptively in some configurations without becoming a
261   reliable general repair. The clearest lesson is methodological: evaluate what the agent completed,
262   which security property was actually observed, and how the implementation relates to the visible
263   procedure before drawing conclusions about memory transfer.

437   Uncertainty. The displayed intervals resample the eligible paired family differences with replace-
438   ment 20,000 times and take the 2.5th and 97.5th percentiles. The reproducible generator uses a fixed
439   analysis seed and retains the two repetitions inside each family unit. These intervals are exploratory
440   and condition on the observed family set; they do not account for uncertainty in task construc-
441   tion, outcome-dependent eligibility, scoring scope, or all possible repeated agent generations. Zero
442   observed variation produces a degenerate bootstrap distribution, not a precise population guarantee.
