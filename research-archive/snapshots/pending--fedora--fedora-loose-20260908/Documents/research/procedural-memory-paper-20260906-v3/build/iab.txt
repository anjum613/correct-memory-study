                                                         Abstract
 1             A procedure can be correct where it was learned yet incomplete where it is reused.
 2             We study coding agents supplied with procedural memory in target tasks that
 3             change a security relevant source assumption. Thirteen synthetic families cross
 4             four memory conditions and two repetitions in six model and agent configurations,
 5             yielding 624 recorded runs and 595 technically valid outcomes. The primary end-
 6             point is functional completion that fails a focal security witness. Estimated changes
 7             from supplying correct memory range from −11.5 to +13.6 percentage points
 8             across configurations; every corresponding bootstrap interval includes zero. Lower
 9             endpoint values sometimes accompany lower functionality. A generic applicability
10             reminder lowers the endpoint in all three Codex configurations, including under
11             bounds for missing outcomes in the fixed recorded cohort; the MiniSWE configu-
12             rations do not share that pattern. In a 52-run sample selected by a fixed rule, two
13             model assisted coding passes agree on 22 implementations with a target protection
14             but only 7 with explicit assumption recognition in the visible trace before editing.
15             Matched transcripts and patches show unchecked reuse, successful adaptation,
16             and distinct mechanisms behind the same measured failure. These observations
17             distinguish three outcomes of procedural transfer that a single success metric can
18             conflate: adaptation, functional completion with a focal violation, and failure to
19             complete.


20   1    Introduction
21   Procedural memory lets an agent reuse a successful method without deriving it again. Yet success is
22   conditional. A record may have been complete before reaching a parser; a cache may have belonged
23   to one request; a diagnostic object may have contained only public fields. If the target changes these
24   assumptions, a memory can accurately describe the source task while providing an incomplete guide
25   to the new one.
26   Consider the status renderer in family F08. In the source context, a status value is a decimal integer,
27   so interpolating it into HTML cannot introduce markup. The target task changes that value to caller
28   controlled text. A small change in the input contract, with a different security consequence. Direct
29   reuse still renders a status message, but fails the focal injection witness; a correct adaptation escapes
30   the text before interpolation. The memory remains accurate about its source, while its applicability
31   changes at the target boundary.
32   We ask: when a coding agent receives a source procedure in a target context where its assumptions
33   no longer hold, how does that memory change functional completion and focal security failures?
34   We also test a generic applicability reminder. Four memory conditions share the same target task

35   and changed assumption (Figure 1). The original hypothesis predicted that correct memory would
36   increase functional completions that violate the focal property. That prediction is not established
37   across the six configurations. The implementation evidence explains why the aggregate endpoint
38   needs care: an agent can adapt the procedure, omit the required check, or avoid the violation by
39   failing to implement the feature.
40   The study contributes (1) a controlled benchmark of thirteen security relevant applicability shifts;
41   (2) a six configuration experiment that separates functionality from focal witness failure; and (3)
42   implementation and visible trace evidence that distinguishes unchecked reuse, target appropriate
43   protection, and failure to complete. The shifts span caller controlled paths, deferred resource lifetimes,
44   cross user caches, origin changes, repeated control fields, concurrency invariants, and approximate
45   authorization evidence. The comparisons preserve this task diversity while holding each target fixed
46   across memory conditions.
47   All targets contain a context shift, and memories are supplied directly. The intervention therefore
48   estimates the effect of supplied memory in those targets; it does not identify the effect of context shift
49   or evaluate a retrieval system. Comparisons are made within each model and agent configuration.

50   2    Related work
51   Memory and applicability. Voyager stores reusable executable skills, while ExpeL extracts natural
52   language lessons from experience without updating model parameters [Wang et al., 2023, Zhao et al.,
53   2023]. Kim et al. [2026] study four memory representations across six coding benchmarks and find
54   that abstract insights transfer more reliably than concrete traces. Our experiment supplies a procedure
55   valid at the source to a target with a changed security relevant assumption.
56   Boundary-Aware Skill Memory (BASM) is the closest applicability aware method [Lin et al., 2026].
57   It augments skills with applicability conditions, risk cues, avoidance rules, and recovery notes,
58   combining retrieval, conditioned execution, and local repair. Our B arm tests a single generic
59   reminder attached to a supplied memory. Prior work asks whether skills transfer or how to make them
60   aware of applicability boundaries. Our contribution is a controlled evaluation with explicit source
61   assumptions, fixed shifted targets, and separate functionality and focal security observations.

62   Skill induced regressions. SWE-Skills-Bench measures the marginal utility of supplied skills in
63   repository software tasks and reports limited average gains and failures of context compatibility [Han
64   et al., 2026]. Dong et al. [2026] compare paired runs to examine functional failures and efficiency


                                                         2
65    regressions induced by loaded skills. We distinguish failure to implement a feature from implementing
66    it while violating a separately evaluated focal property, then connect those outcomes to visible
67    statements and implementation changes.

68    Security and the execution interface. SecureVibeBench reconstructs vulnerability introducing
69    scenarios in 105 C/C++ tasks from 41 OSS-Fuzz projects and combines functionality and security
70    evaluation [Chen et al., 2026]. Its repository tasks complement our controlled memory intervention.
71    Experience driven self evolution can also trade safety against task utility in web and embodied
72    settings [Zhao et al., 2026]; our measured behavior is the generated implementation rather than
73    refusal of a harmful request. Finally, SWE-agent demonstrates that the agent computer interface
74    affects software engineering performance [Yang et al., 2024]. Different tool surfaces and execution
75    budgets are therefore part of each evaluated configuration, and interface related failure to complete
76    changes the interpretation of a focal witness pass.

77    3   Task construction and experimental design
78    Source validity and changed assumptions. Each family pairs a source setting where a procedure
79    is valid with a target feature request that changes a relevant assumption. The final suite contains
80    six F-series and seven X-series synthetic families, covering parsing, lifetimes, paths, rendering,
81    identity, confidentiality, and state consistency. Existing baseline code is visible in every condition. N
82    removes supplied memory, not the task’s implementation. Appendix A gives the family contracts and
83    construction records.

84    Reference controls. The saved preflight checks three target states in each family: an incomplete
85    baseline that fails functionality and passes the focal witness, an unadapted functional reference that
86    fails the witness, and a repaired reference that passes both. Avoiding the requested feature is therefore
87    insufficient for success. The final manifest fixes the artifacts and source procedures. Constructors and
88    evaluated agents are separate roles; constructors do not receive sealed witnesses or evaluated agent
89    outcomes.

95    Memory conditions. The conditions are no memory (N), correct source memory (C), matched
96    irrelevant memory (I), and correct source memory with a generic applicability boundary (B). C, I,
97    and B each contain a 4,096 byte envelope including neutral padding; N has none. Bytes, not tokens,
98    are equalized. The B reminder asks whether the source assumption still holds and supplies no target
99    repair. C−N is the frozen primary contrast and estimates the effect of supplying the correct source
100   memory as a whole, including any generic effect of added context. I−N and C−I help diagnose that
101   contribution but do not perfectly isolate semantic memory content. B−C tests the generic boundary
102   reminder.

125   4   Results
126   Joint outcomes separate focal passes from failure to complete. Figure 2 retains all recorded
127   runs and separates the four possible functionality and focal witness outcomes. For Qwen 30B, C−N
128   lowers U by 11.5 percentage points, but functional runs fall from 24 to 20 out of 26 and functionality
129   and focal witness passes fall from eight to seven. The lower endpoint therefore does not represent an
130   improvement that preserves functionality. Qwen Next and Luna also have substantial ¬F ∧ S mass;
131   saved traces link part of Luna’s failure to complete to a mismatch between named and available tools.
132   These are functional failures, not evidence of protection.

133   Correct memory estimates differ in direction. Figure 3 shows the corrected comparisons within
134   each configuration. C−N changes U by +9.1, +13.6, and +4.2 percentage points in the GPT-5.5,
135   Luna, and Terra Codex configurations. The MiniSWE estimates are 0.0, −11.5, and −4.2 points for
136   Qwen Next, Qwen 30B, and Devstral. These are observed differences among configurations; the
137   study does not resolve whether their underlying effects differ.

138   The applicability reminder shows a configuration specific pattern. B−C estimates for U are
139   −30.0, −13.6, and −22.7 points in the three Codex configurations. Functionality is unchanged for
140   GPT-5.5 and Terra and rises by +4.5 points for Luna. The MiniSWE estimates are 0.0, +4.2, and 0.0
141   points. Since the harnesses differ in tools, interfaces, instructions, and budgets, this is a pattern among
142   complete configurations rather than a model level effect. Bounds that retain completed outcome
143   components remain entirely negative for all three Codex configurations under every admissible
144   assignment of unresolved recorded outcomes. These bounds concern the fixed recorded cohort;
145   they are separate from sampling uncertainty. Appendix D gives the bounds and treatment specific
146   missingness; Appendix E gives sign flip and family omission diagnostics.

153   5   Exploratory behavioral analysis

154   Sampling and coding. After the experiments, we froze a codebook and sampling rule before
155   annotation. One run was sampled from every family and condition cell, giving 52 runs, with eight or
156   nine per configuration. The rule used design labels and random repetition selection, without outcomes
157   or trace availability; no run was replaced. All selected traces and implementations were available.
158   Two isolated LLM sessions read every packet separately, with final scores and model labels withheld.
159   Both used the recorded OpenAI alias gpt-6-astra with xhigh reasoning (Appendix F). Packets
160   contained the task, a source procedure for comparison, initial and final implementations, the patch,
161   and chronological visible tool interactions. Interfaces and public feedback remained visible.
162   The dimensions distinguish explicit assumption recognition in the visible trace before editing (A),
163   retention of a recognizable source procedure without its target check (P), a concrete target protection
164   (T), and stopping without a meaningful implementation (Z). Each decision includes event or imple-
165   mentation line anchors. Labels are yes, no, uncertain, and unavailable. The passes could not inspect
166   each other’s output; disagreements were retained without outcome based adjudication.

167   Visible statements and implemented protection are distinct observations. Both passes identify
168   explicit assumption recognition before editing in 7 runs, procedure retention without the check in
169   20, concrete protection in 22, and no meaningful implementation in 7 (Table 2). All seven runs
170   with agreed explicit assumption recognition also have agreed protection. Fifteen further runs have
171   agreed protection without that agreed visible statement. The visible trace therefore does not provide a
172   complete account of when protections enter the implementation. These codes do not identify whether
173   memory influenced an edit, particularly in conditions where no source memory was delivered.

197   6    Measurement implications and discussion
198   Observe required behavior rather than implementation bookkeeping. X05 and X28 expose a
199   measurement problem: an implementation can return a contract relevant result without populating
200   an optional ledger. Evaluators should observe required outputs and externally visible effects, using
201   internal traces as supporting evidence. X06 illustrates a second distinction. Its mixed record witness
202   establishes confidentiality without requiring useful public output. Appendix G specifies prospective
203   output rules separately from the historical results.

204   Limitations. The synthetic tasks provide explicit source assumptions and separately testable func-
205   tionality and focal properties; thirteen selected families with two repetitions offer limited precision
206   and do not establish repository scale external validity. Their trust shifts cover a constrained part of
207   procedural applicability. The exploratory behavioral analysis uses two model assisted passes, with
208   eight disagreements and no human validation. Retrieval, naturally occurring histories, and longer
209   term memory dynamics remain outside the supplied memory intervention.

210   7    Conclusion
211   Supplying correct procedural memory produced both unchecked reuse and successful adaptation
212   in the saved coding trajectories. The aggregate endpoint also fell when agents completed fewer
213   tasks, showing why a reduction in functional focal violations is insufficient on its own. A generic
214   applicability reminder had a consistent negative direction in the three Codex configurations, including
215   under the bounds for missing recorded outcomes; the MiniSWE configurations did not share that
216   pattern. Evaluating procedural transfer requires observing task completion, the focal property, and
217   the implementation that connects the two.
