                                                         Abstract
 1             A procedure can be correct where it was learned yet incomplete where it is reused.
 2             We study coding agents supplied with procedural memory in target tasks that
 3             change a security relevant source assumption. Thirteen synthetic families cross
 4             four memory conditions and two repetitions in six model and agent configurations,
 5             yielding 624 recorded runs and 595 technically valid outcomes. The primary
 6             endpoint is functional completion that fails a focal security witness. The effect
 7             of correct memory ranges from −11.5 to +13.6 percentage points across con-
 8             figurations, with positive, zero, and negative estimates. Lower endpoint values
 9             sometimes accompany lower functionality. A generic applicability reminder re-
10             duces the endpoint in all three Codex configurations, a configuration specific
11             direction that survives every assignment of unresolved outcomes in the recorded
12             cohort; the MiniSWE configurations do not share that pattern. In a prespecified
13             52-run sample, two model-assisted coding passes agree on 22 implementations
14             with a target protection but on only seven with explicit assumption recognition in
15             the visible trace before editing. Matched transcripts and patches show unchecked
16             reuse, successful adaptation, and distinct mechanisms behind the same measured
17             failure. Correct procedural memory is therefore neither uniformly beneficial nor
18             uniformly harmful when its source assumptions change, and outcome evaluation
19             must observe functionality and the focal property separately.


20   1    Introduction
21   Procedural memory lets an agent reuse a successful method without deriving it again. Yet success is
22   conditional. A record may have been complete before reaching a parser; a cache may have belonged
23   to one request; a diagnostic object may have contained only public fields. If the target changes these
24   assumptions, a memory can accurately describe the source task while providing an incomplete guide
25   to the new one.
26   Family F08 makes the problem concrete. In the source context, a status value is a decimal integer,
27   so interpolating it into HTML cannot introduce markup. The target task changes that value to caller
28   controlled text. Direct reuse still renders a status message, but fails the focal injection witness; a
29   correct adaptation escapes the text before interpolation. The memory remains accurate about its
30   source, while its applicability changes at the target boundary.
31   We ask: when a coding agent receives a source procedure in a target context where its assumptions
32   no longer hold, how does that memory change functional completion and focal security failures?
33   A second question asks whether a generic applicability reminder changes this behavior. We supply
34   a frozen correct memory, a matched irrelevant memory, correct memory with the reminder, or no

35   memory (Figure 1). The target task and changed assumption remain fixed. The original hypothesis
36   predicted that correct memory would increase functional completions that violate the target’s focal
37   property. The estimates instead have positive, zero, and negative signs across the six configurations,
38   which is inconsistent with a simple universal harmful transfer account in this cohort.
39   The study contributes (1) a controlled benchmark of thirteen security relevant applicability shifts;
40   (2) a six configuration experiment that separates functionality from focal witness failure; and (3)
41   implementation and visible trace evidence that distinguishes unchecked reuse, target appropriate
42   protection, and non-completion. The shifts span caller controlled paths, deferred resource lifetimes,
43   cross user caches, origin changes, repeated control fields, concurrency invariants, and approximate
44   authorization evidence. Together, the results show heterogeneous effects of correct memory and a
45   configuration specific response to a generic applicability reminder.
46   All targets contain a context shift, and memories are supplied directly. The intervention therefore
47   estimates the effect of supplied memory in those targets; it does not identify the effect of context shift
48   or evaluate a retrieval system. Comparisons are made within each model and agent configuration.


49   2    Related work

50   Memory and applicability. Voyager stores reusable executable skills, while ExpeL extracts natural
51   language lessons from experience without updating model parameters [Wang et al., 2023, Zhao
52   et al., 2023]. These systems motivate procedural reuse, but successful transfer is conditional on
53   what the memory preserves. Kim et al. [2026] study four memory representations across six coding
54   benchmarks and find that abstract insights transfer more reliably than concrete traces. Our experiment
55   fixes a procedure valid at the source and changes its relevance to a target security contract; the
56   endpoint distinguishes task non-completion from a functional security violation.
57   Boundary-Aware Skill Memory (BASM) is the closest applicability aware method [Lin et al., 2026].
58   It augments skills with applicability conditions, risk cues, avoidance rules, and recovery notes, and
59   combines retrieval, conditioned execution, and local repair. It also investigates wrong tool preference
60   using attention and intervention analyses. Our B arm is a single generic reminder attached to a
61   supplied memory. It neither implements BASM nor tests its structured mechanism. Prior work asks
62   whether skills transfer or how to make them aware of applicability boundaries. We hold a source
63   valid procedure fixed, change the target assumption, and separately observe functionality and a focal
64   security property. We do not claim novelty for the general observation that a relevant skill can become
65   inapplicable.

66   Skill induced regressions. SWE-Skills-Bench measures the marginal utility of supplied skills in
67   repository software tasks and reports limited average gains and failures of context compatibility [Han
68   et al., 2026]. Dong et al. [2026] use differential analysis of paired runs to examine functional failures
69   and efficiency regressions induced by loaded skills. Their results make clear that procedural guidance
70   can constrain implementation in unhelpful ways. Our focal distinction is between failing to implement

72    analysis separates visible statements, implementation changes, and measured outcomes.

73    Security and the execution interface. SecureVibeBench reconstructs vulnerability introducing
74    scenarios in 105 C/C++ tasks from 41 OSS-Fuzz projects and combines functionality and security
75    evaluation [Chen et al., 2026]. We cite its ACL 2026 version, which supersedes the earlier arXiv
76    report. Its repository realism addresses a different objective from our synthetic memory intervention.
77    Experience driven self evolution can also trade safety against task utility in web and embodied
78    settings [Zhao et al., 2026]; our measured behavior is the generated implementation rather than
79    refusal of a harmful request. Finally, SWE-agent demonstrates that the agent computer interface
80    affects software engineering performance [Yang et al., 2024]. This matters directly here: different
81    tool surfaces and execution budgets are part of each evaluated configuration, and interface related
82    non-completion changes the meaning of a focal witness pass.

83    3   Task construction and experimental design
84    Source validity and changed assumptions. Each family pairs a source setting where a procedure
85    is valid with a target feature request that changes a relevant assumption. The final suite contains
86    six F-series and seven X-series synthetic families, covering parsing, lifetimes, paths, rendering,
87    identity, confidentiality, and state consistency. Existing baseline code is visible in every condition. N
88    removes supplied memory, not the task’s implementation. Appendix A gives the family contracts and
89    construction records.

90    Reference controls. The saved preflight checks three target states in each family: the incomplete
91    baseline must fail functionality and pass the focal witness; an unadapted functional reference must
92    pass functionality and fail the witness; and a repaired reference must pass both. Thus avoiding the
93    requested feature is insufficient for success. The final manifest fixes the synthetic artifacts and source
94    procedures. Constructors and evaluated agents are separate roles; constructors do not receive sealed
95    witnesses or evaluated agent outcomes. The controls establish these three states, while validation of
96    alternative implementations requires examining what the observer actually measures.

97    Configurations and execution. The six configurations each complete their 104-run schedule, pro-
98    ducing 624 recorded runs: 595 technically valid and 29 invalid. Codex and MiniSWE have different
99    native interfaces, instruction envelopes, and budgets. Requested aliases are preserved; backend
100   identities are not inferred. Executed manifests record run order. A seventh planned configuration
101   is excluded because quota exhaustion left its cohort unfinished; this retrospective scope decision is
102   documented, and none of its outcomes or examples are used (Appendix C).

103   Memory conditions. The conditions are no memory (N), correct source memory (C), matched
104   irrelevant memory (I), and correct source memory with a generic applicability boundary (B). C, I,
105   and B each contain a 4,096 byte envelope including neutral padding; N has none. Bytes, not tokens,
106   are equalized. The B reminder asks whether the source assumption still holds and supplies no target
107   repair. C−N is the frozen primary contrast and estimates the effect of supplying the correct source
108   memory as a whole, including any generic effect of added context. I−N and C−I help diagnose that

111   Outcomes and scoring. For a technically valid run, F denotes functionality pass and S focal
112   security witness pass. The primary endpoint is

113   All four joint outcomes are reported. In particular, ¬F ∧ S is a functional failure, while F ∧ S means
114   functionality and focal witness pass. Technical invalids retain missing F/S/U values in the primary
115   table. Termination labels do not override evaluations.
116   A versioned validity review changed four Devstral focal witness labels because the X05 and X28
117   observers had inspected optional internal ledgers rather than required return values and effects. The
118   correction is narrowly scoped, preserves the original scores, changes no functionality or validity
119   label, and leaves the qualitative C−N conclusion unchanged. Appendix C gives the full scoring
120   history. X06 retains its executed confidentiality scope: rejecting the mixed record can pass without
121   demonstrating retention of useful public fields.

122   Primary analysis. A family is eligible for a contrast when both repetitions in both compared
123   conditions are valid with observed F and S. We average repetitions within family and condition, then
124   average paired differences equally over eligible families. Tables report the eligible count. Exploratory
125   95% percentile intervals use 20,000 paired family bootstrap resamples. Exact sign flip and family
126   omission diagnostics appear in Appendix E. These are comparisons within configurations, not a
127   ranking of model security.

128   Measurement availability and bounds. A separate review distinguishes interruption, timeout,
129   candidate execution exception, and evaluator incompatibility. Completed outcome components are
130   retained, while unresolved components remain unknown. Appendix D reports treatment specific
131   counts and bounds over every assignment of the unresolved outcomes consistent with the completed
132   observations.

133   4   Results
134   Joint outcomes separate adaptation from non-completion. Figure 2 retains all recorded runs and
135   separates the four possible functionality and focal witness outcomes. For Qwen 30B, C−N lowers
136   U by 11.5 percentage points, but functional runs fall from 24 to 20 out of 26 and functionality and
137   focal witness passes fall from eight to seven. The lower endpoint therefore does not represent an
138   improvement that preserves functionality. Qwen Next and Luna also have substantial ¬F ∧ S mass;
139   saved traces link part of Luna’s non-completion to a mismatch between named and available tools.
140   These are functional failures, not evidence of protection.

141   Correct memory has heterogeneous effects. Figure 3 shows the corrected within-configuration
142   comparisons. C−N changes U by +9.1, +13.6, and +4.2 percentage points in the GPT-5.5, Luna,
143   and Terra Codex configurations. The MiniSWE estimates are 0.0, −11.5, and −4.2 points for Qwen
144   Next, Qwen 30B, and Devstral. Every C−N bootstrap interval includes zero. The positive, zero, and
145   negative estimates do not support a universal directional account in the evaluated cohort.

146   The applicability reminder shows a configuration specific pattern. B−C lowers U by 30.0,
147   13.6, and 22.7 points in the three Codex configurations. Functionality is unchanged for GPT-5.5 and
148   Terra and rises by 4.5 points for Luna. The MiniSWE estimates are 0.0, +4.2, and 0.0 points. Since
149   the harnesses differ in tools, interfaces, instructions, and budgets, this is a pattern among complete
150   configurations rather than a model level effect. Bounds that preserve completed outcome components
151   remain entirely negative for all three Codex configurations under every admissible assignment of
152   unresolved recorded outcomes. Appendix D gives the bounds and treatment specific missingness;
153   Appendix E gives sign flip and family omission diagnostics.

160   5       Exploratory behavioral analysis

161   Sampling and coding. We froze a four-dimension codebook and sampled one run from every family
162   and condition cell, giving 52 runs. Configuration assignments were shuffled and balanced to eight or
163   nine runs each; a repetition was selected at random. Selection used design labels, without outcomes or
164   trace availability, and no run was replaced. All 52 selected traces and implementations were available.
165   Two isolated LLM sessions independently read every packet, with final scores and model labels
166   withheld. Both sessions record the OpenAI model alias gpt-6-astra, xhigh reasoning, and Codex
167   CLI 0.153.4; no backend revision is exposed. Each packet contained the task, a source procedure for
168   comparison, the initial implementation, chronological visible statements and tool interactions, and
169   the final implementation and patch. Tool interfaces and public feedback remained visible.
170   The dimensions distinguish explicit assumption recognition in the visible trace before editing (A),
171   retention of a recognizable source procedure without its target check (P), a concrete target protection
172   (T), and stopping without a meaningful implementation (Z). Each decision includes event or imple-
173   mentation line anchors. Labels are yes, no, uncertain, and unavailable. The passes could not inspect
174   each other’s output; disagreements were retained without outcome based adjudication.

175   Visible statements and implemented protection are distinct observations. Both passes identify
176   explicit assumption recognition before editing in 7 runs, procedure retention without the check in
177   20, concrete protection in 22, and no meaningful implementation in 7 (Table 2). All seven runs

202   complete functionally and fail the focal witness. Their patches reopen or reread the slot at callback

207   6    Measurement implications and discussion
208   Observe required behavior rather than implementation bookkeeping. The X05 and X28
209   corrections arose because alternative implementations could return a contract relevant result without
210   populating an optional internal ledger. Applying the contract based rule to all 144 saved submissions
211   in the three reviewed families changed four focal witness labels. This gives a practical rule for agent
212   benchmarks: evaluate required outputs and externally visible effects, and use internal traces only
213   as supporting evidence. X06 shows the complementary problem. Its executed witness establishes
214   confidentiality for one mixed record, but does not establish delivery of useful public fields. Prospective
215   X06 and F08 output rules are recorded in Appendix G and do not alter the historical results.

216   Limitations. The controlled synthetic tasks provide explicit source assumptions and independently
217   testable functionality and focal properties, but thirteen families with two repetitions do not establish
218   external validity for repository scale software engineering. The families cover a constrained set
219   of trust shifts rather than the full range of changes that can alter a procedure’s applicability. The
220   52-run behavioral analysis is exploratory and based on two model-assisted coding passes, with eight
221   disagreements and no human validation. The experiment isolates supplied procedural memory under
222   controlled target conditions; retrieval quality, naturally occurring repository histories, longer term
223   memory dynamics, and model specific mechanisms require external validation.

224   7    Conclusion
225   Correct memory produced positive, zero, and negative changes in functional focal witness failures
226   across the six configurations. Lower endpoint values sometimes reflected lost functionality, while
227   matched traces showed both unchecked reuse and successful target adaptation. A generic boundary
228   reminder reduced the endpoint in all three Codex configurations, including under the missing outcome
229   bounds, but the MiniSWE configurations did not share that pattern. Correct procedural memory
230   therefore cannot be treated as uniformly beneficial or harmful when applicability assumptions
231   change. Evaluating transfer requires observing both task completion and the property that the original
232   procedure implicitly relied on.
