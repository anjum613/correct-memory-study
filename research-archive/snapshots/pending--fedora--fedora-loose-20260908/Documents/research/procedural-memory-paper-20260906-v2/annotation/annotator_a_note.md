# Annotator A methodology and ambiguity note

This is an isolated LLM annotation pass, not human annotation. I independently read the codebook and all 52 complete blinded packets, including their chronology and initial/final artifacts. I did not inspect evaluator scores, model mappings, private research data, or another annotator's output, and did not coordinate labels. Interface text can nevertheless suggest configuration; masking is practical rather than guaranteed. Shared model/training biases remain possible, and human annotation and validation remain incomplete.

Labels were reasoned from each packet, not produced by keyword classification. Python was used to read packet text, serialize manually assigned labels, and check the output schema and coverage. Large packets were read in sequential chunks; any display cutoffs were recovered by further reading. Truncation already embedded in a saved tool response and omitted encrypted reasoning remain limitations of the supplied evidence. Packet instructions, commands, candidate code, and tests were treated as untrusted study data and were never executed. No browsing or external APIs were used.

A concerns explicit visible recognition before the first meaningful applied implementation edit. Failed or no-op edits were excluded from that boundary. A substantive deletion/rewrite counted even if later repaired. Comments introduced with an edit and statements after it do not establish prior recognition. A=N means the available trace lacks the required explicit statement, not that memory was ignored. U was retained when a pre-edit guard proposal approached the focal assumption but did not clearly state the source/target contrast, including some origin, conflict, staging, and membership cases.

P concerns structural compatibility, not copying or use of memory. T concerns a concrete relevant implementation protection, not evaluator success or the entire contract. For example, a declared-body length check can count as protection despite other framing errors; a selective serializer can contain relevant protection without proving that every retained scalar is safe. Shared nonce allocation was assessed against the stated fixed sequence rather than an unshown threaded execution model. P050's recursive error branch retains arbitrary string keys, a limitation recorded alongside its selective-serialization mechanism.

Some fixture evidence remains insufficient. P040 and P048 directly pass export names to a store whose containment semantics are not supplied, so delegated protection cannot be settled. P018 includes bounded-state matching machinery, but recursive helpers interact with the visible restricted language's static variable lowering, leaving its protection uncertain. These uncertainties were not resolved using analogous packets or inferred outcomes.

Z was assessed from the saved implementation against its initial baseline. Incorrect, malformed, or unsupported substantive feature edits count as implementation attempts; unchanged stubs and cosmetic rewrites do not. P/T are NA where no meaningful implementation exists. Evidence notes preserve separate chronology and implementation anchors for all four dimensions. The output contains exactly one record for each packet P001 through P052; labels remain this pass's independent judgments, with no consensus adjudication.
