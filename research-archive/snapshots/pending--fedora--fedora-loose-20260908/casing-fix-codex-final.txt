## Root cause

`GitHubEvidence._key()` hashes the exact, case-sensitive endpoint.

- Capture constructed linked-PR evidence endpoints from GraphQL `nameWithOwner`, e.g. `/repos/ExampleOwner/ExampleRepository/pulls/9`.
- Materialization read REST repository metadata first, then constructed PR/commit/tree lookup endpoints from REST `owner.login` and `name`, e.g. `/repos/exampleowner/examplerepository/pulls/9`.

These produced different evidence hashes, causing `RAW_CAPTURE_INCOMPLETE`.

## Change made

Changed `_captured_pr_episode()` only:

- Keeps the REST-derived exact lookup as the default.
- When REST and GraphQL coordinates differ only by case, checks whether persisted evidence exists under the originally requested GraphQL-cased PR endpoint.
- If so, consistently uses that casing for PR, commit-list, commit, and tree lookups.
- Does not normalize or change persisted evidence keys.
- Preserves same-casing behavior, original captured casing, dependency order, and 404/410 behavior.
