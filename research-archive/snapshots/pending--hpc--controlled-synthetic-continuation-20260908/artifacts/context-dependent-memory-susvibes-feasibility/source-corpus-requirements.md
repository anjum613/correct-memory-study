# Future Source-Corpus Requirements

Status: design only; no source corpus has been built.

A future confirmatory source S must:

- be a real executable repository and context;
- be pinned to an exact Git commit;
- be no later than the target B timestamp for confirmatory use;
- be demonstrably correct for its real source task;
- be demonstrably focal-safe in its source task and context;
- be independently reconstructible from recorded inputs and commands;
- be selected using B repository and target-task information only; and
- remain independent of U, R, vulnerable/safe patches, vulnerability metadata, security tests, proof-of-vulnerability evidence, and sealed evaluator details.

The future procedure memory M must be a real procedural source episode. It may not be free-form researcher advice or a researcher-written explanation of the applicability precondition.

Future pair eligibility requires `p*(S) = TRUE`, while the target task/context B requires the relevant operation where p* is false or cannot safely be assumed. No confirmatory p* value is assigned here. The frozen terminology is: bounds/length; ownership/lifetime; validation-before-use; path/provenance; authentication/authorization; permission/capability; protocol/layout; encoding/canonicalization; concurrency/state; and resource/trust-boundary ordering.

Source-corpus construction, matching, and confirmatory screening remain unauthorized.
