\paragraph{Admission and non-completion controls.}
The final construction manifest binds six retained F families and seven admitted X families to immutable specifications and candidate artifacts. The X construction pool had 26 attempted families, 16 with a retained machine-valid candidate, and seven admitted to the final cohort. These are synthetic construction counts, not counts selected from a repository corpus. The source-valid state establishes where the remembered procedure applies. Target controls distinguish an incomplete baseline ($F=0,S=1$), a functional unadapted implementation ($F=1,S=0$), and a functional repair ($F=1,S=1$). The saved Codex preflight checks these target roles for all thirteen families. Reference repairs are controls, not required implementation templates. The later observer corrections show that passing those controls did not guarantee observation of every behavior produced by an alternative implementation.

\paragraph{Construction and evaluation separation.}
In the X-family protocol, the constructor authors incomplete and functional target components; the unadapted target implementation is derived from the frozen source-context implementation, and patches are produced deterministically. Constructors do not receive researcher tests, sealed witnesses, reference states, evaluated-agent outcomes, or admission judgments. At most four constructor attempts per attempted family are permitted, retaining the first machine-valid candidate. The final source memories and irrelevant pairings are fixed in the experiment manifest.

\section{Analysis specification and sensitivity}
\label{app:sensitivity}
For configuration $m$, contrast $a-b$, and outcome $Y\in\{F,S,U\}$, let $\mathcal{E}_{m,a,b}$ contain families for which both repetitions in both conditions are technically valid and have observed F and S. The estimate is
\begin{equation}
\widehat{\Delta}_{m,a-b}^{Y}=\frac{1}{|\mathcal{E}_{m,a,b}|}\sum_{f\in\mathcal{E}_{m,a,b}}\left[\frac{Y_{m,f,a,1}+Y_{m,f,a,2}}{2}-\frac{Y_{m,f,b,1}+Y_{m,f,b,2}}{2}\right].
\end{equation}
We multiply by 100 to report percentage points. Eligible sets are contrast-specific. The correction changes no eligibility decisions. There is no pooled model ranking or substitution of an invalid repetition by an offline result.

\paragraph{Uncertainty.}
The displayed intervals resample the eligible paired family differences with replacement 20,000 times and take the 2.5th and 97.5th percentiles. The reproducible generator uses a fixed analysis seed and retains the two repetitions inside each family unit. These intervals are exploratory and condition on the observed family set; they do not account for uncertainty in task construction, outcome-dependent eligibility, scoring scope, or all possible repeated agent generations. Zero observed variation produces a degenerate bootstrap distribution, not a precise population guarantee.

The two-sided family sign-flip diagnostic enumerates sign assignments to the family differences and requires a symmetry/exchangeability assumption. It is not a randomization test justified by randomized signs in this design. Leave-one-family-out ranges describe the influence of individual observed families. Scope omissions and these diagnostics were chosen during review and are not replacement primary analyses.

\section{Behavioral evidence and reproducibility}
The anonymized analysis package contains all 624 outcome rows, original and corrected labels, configuration records, exact contrast eligibility, generated tables, plotting/analysis code, and the six transcript excerpts used in the matched panels. Stable record identifiers bind excerpts to outcomes. The private claim ledger additionally records original run IDs, native transcript locations, final patches, saved evaluator outputs, source paths, and hashes. Personal paths, local hostnames, native session identifiers, and private evidence copies are excluded from the reviewer package.

The two outcome-aware audit casebooks are exploratory aids. Pending coding fields are not a completed codebook application. The F02 mechanism comparison and the F20 source-as-task example are selected supporting interpretations tied to saved artifacts; they are not frequency estimates. No encrypted reasoning is interpreted. In particular, failure does not establish copying, and absence of a memory mention does not establish that the memory was ignored.

The analysis is regenerated from saved data with \texttt{make analyze}; both wrappers build with \texttt{make all}. It requires no model credentials, paid inference, repository candidate execution, or evaluator change. The source-of-truth CSV and its correction are preserved in the private evidence copy, and the public table retains the same statistical information without identifying paths.
