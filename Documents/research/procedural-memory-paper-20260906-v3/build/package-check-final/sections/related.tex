\section{Related work}
\paragraph{Memory and applicability.}
Voyager stores reusable executable skills, while ExpeL extracts natural language lessons from experience without updating model parameters~\citep{voyager,expel}. \citet{mtl} study four memory representations across six coding benchmarks and find that abstract insights transfer more reliably than concrete traces. Our experiment supplies a procedure valid at the source to a target with a changed security relevant assumption.

Boundary-Aware Skill Memory (BASM) is the closest applicability aware method~\citep{basm}. It augments skills with applicability conditions, risk cues, avoidance rules, and recovery notes, combining retrieval, conditioned execution, and local repair. Our B arm tests a single generic reminder attached to a supplied memory. Prior work asks whether skills transfer or how to make them aware of applicability boundaries. Our contribution is a controlled evaluation with explicit source assumptions, fixed shifted targets, and separate functionality and focal security observations.

\paragraph{Skill induced regressions.}
SWE-Skills-Bench measures the marginal utility of supplied skills in repository software tasks and reports limited average gains and failures of context compatibility~\citep{sweskills}. \citet{harmfulskills} compare paired runs to examine functional failures and efficiency regressions induced by loaded skills. We distinguish failure to implement a feature from implementing it while violating a separately evaluated focal property, then connect those outcomes to visible statements and implementation changes.

\paragraph{Security and the execution interface.}
SecureVibeBench reconstructs vulnerability introducing scenarios in 105 C/C++ tasks from 41 OSS-Fuzz projects and combines functionality and security evaluation~\citep{securevibebench}. Its repository tasks complement our controlled memory intervention. Experience driven self evolution can also trade safety against task utility in web and embodied settings~\citep{experience_safety}; our measured behavior is the generated implementation rather than refusal of a harmful request. Finally, SWE-agent demonstrates that the agent computer interface affects software engineering performance~\citep{sweagent}. Different tool surfaces and execution budgets are therefore part of each evaluated configuration, and interface related failure to complete changes the interpretation of a focal witness pass.
