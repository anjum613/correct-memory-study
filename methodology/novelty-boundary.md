# Novelty boundary

Protocol version: `benchmark-selection-v0.1`

This is a prospective methodological boundary, not a claim that novelty has
already been established by a completed literature review. Related-work claims
must be coded from cited source text before publication.

## Residual contribution

The exact residual contribution is:

> randomised within-target exposure to a fidelity-valid but
> trust-incompatible repair memory, under a matched semantic
> trust-boundary change, with:
>
> - a functionally passing patch;
> - a security witness blocked before and successful afterward;
> - execution-grounded grading of the decisive condition;
> - a token-matched placebo completion;
> - a true-condition/check/adaptation completion.

The causal unit is the within-target contrast after the repository, task,
decisive condition, validation machinery, and treatment-independent execution
protocol have been frozen. Benchmark selection and replacement are completed
without treatment outcomes.

## Boundary conditions

- The base is a real open-source repository at an immutable commit.
- Source, compatible-target, and trust-invalidated-target variants are minimal
  controlled unpublished variants derived from that base.
- One narrow, observable decisive precondition `p*` separates faithful reuse
  from the secure reference in the invalidated target.
- Faithful reuse must pass the functional oracle and open the intended security
  witness. The secure reference must pass the same functional oracle and keep
  that witness blocked.
- The security witness and functional oracle are executable and deterministic;
  the functional oracle is implementation-independent.
- Selection evidence, independent review, tie-breaking, reserves, and the
  benchmark freeze precede all memory-treatment runs.

## Claims outside the boundary

The study does not claim as individually novel:

- harmful or mismatched skills;
- omitted preconditions;
- implicit-requirement failures;
- coding-agent vulnerabilities;
- security oracles;
- memory poisoning;
- general unsafe self-evolution.

Those topics may be related or motivating contexts. They cannot be presented
as the residual contribution without a separate, source-grounded claim.

## Permitted external-validity wording

The frozen benchmark is a purposive, stratified sample of controlled tasks
derived from real open-source repositories. It supports causal inference about
the specified within-target treatment contrast under the frozen protocol. It
does not estimate the prevalence of this failure mode across repositories,
agents, models, vulnerability classes, or production software.
